mneme is a Rust workspace. The fastest way to see it running is Docker (no
toolchain) or a single `make` target; building from source is the third option.
Every path lands you on the same live dashboard at `http://localhost:7777`.

## Fastest — no Rust toolchain (Docker)

Builds and runs the server in a container and serves the live dashboard with
**zero external downloads** on first boot (mock embedder + synthetic writer):

```bash
git clone https://github.com/aniketshukla1/mneme.git && cd mneme
docker compose up --build
```

Open `http://localhost:7777`. For real, persistent use, set `MNEME_DEMO=0` and
`MNEME_EMBEDDER=fastembed` in `docker-compose.yml` (fastembed downloads
`bge-small-en-v1.5` on first run; the log persists in the `mneme-data` volume).

## With Rust installed — one word

```bash
git clone https://github.com/aniketshukla1/mneme.git && cd mneme
make demo     # instant demo: live dashboard, zero downloads (mock embedder + learning curve)
```

Other targets (`make` on its own lists them all):

| Target | What it does |
| --- | --- |
| `make demo` | Instant demo — mock embedder, synthetic writer, live procedural learning curve |
| `make run` | Real server — persistent log + fastembed embeddings |
| `make test` | The workspace test suite |
| `make lint` | Exactly what CI enforces (`fmt --check` + `clippy -D warnings`) |
| `make mcp` | Install the MCP binary for Claude Desktop / Cursor / any MCP client |
| `make docker` | The Docker path above |

## From source

<Steps>

1. Prerequisites: **Rust** (stable, 1.75+, via [rustup](https://rustup.rs)) and
   a C toolchain (for native deps like `tantivy` and `hnsw_rs`).

2. Clone and build the workspace:

   ```bash
   git clone https://github.com/aniketshukla1/mneme.git
   cd mneme
   cargo build --release
   ```

3. Run the tests and lint exactly as CI does:

   ```bash
   cargo test
   cargo fmt --check
   cargo clippy -- -D warnings
   ```

</Steps>

## Run the server + dashboard

The host process (`mneme-server`, binary name `mneme`) exposes an HTTP API and a
live dashboard.

```bash
# Real embeddings (fastembed, 384-d) — downloads bge-small on first run:
cargo run --release -p mneme-server

# Or offline/instant with the deterministic mock embedder (no download):
MNEME_EMBEDDER=mock cargo run --release -p mneme-server
```

Open `http://localhost:7777`. The dashboard surfaces live panels for retrieval
metrics, memory evolution, the procedural learning curve, and each frontier
phase (causal, probe, KV, exchange, dream, provenance).

<Aside type="tip">
Add `MNEME_DEMO=1` for a fresh temp data dir plus a synthetic writer, and
`MNEME_PROCEDURAL=on` to spawn the procedural compiler worker. The default build
uses deterministic stand-ins so everything runs offline; point the LLM-backed
features at a running Ollama with `MNEME_EVOLVE_LLM=ollama`.
</Aside>

### Key environment variables

| Env var | Default | Meaning |
| --- | --- | --- |
| `MNEME_PORT` | `7777` | HTTP listen port |
| `MNEME_HOST` | `127.0.0.1` | Bind address; the Docker image sets `0.0.0.0` |
| `MNEME_DATA` | `./mneme-data` | Path to the fjall keyspace |
| `MNEME_EMBEDDER` | `fastembed` | `mock` for the 32-d deterministic embedder (no download) |
| `MNEME_DEMO` | `0` | `1` → temp data dir + synthetic writer |
| `MNEME_PROCEDURAL` | `off` | `on` → spawn the procedural compiler worker |

## Storage layout

mneme persists to a single append-only event log (fjall-backed) plus its
materialized views. By default it lives under `./mneme-data`. Because the log is
the single system of record, **every index is rebuildable by replaying events** —
deleting a view directory and restarting reconstructs it.
